# 项目四 · 经营数据日报生成器（PRD）

> 个人项目 / 实战练习。数据为公开示例（演示模式），非真实店铺数据。

## 1. 背景与痛点
- 店主每天手动看生意参谋抄数、算环比，费时且容易漏掉异常。
- 异常发生后（流量骤降、退款率飙升）缺少固定排查思路，反应慢。

## 2. 目标
把"导出数据 → 自动出日报（指标 + 异常 + 建议）"做成一键流程，把人从抄数里解放出来。

## 3. 用户故事
- 作为店主，我导入一天的 CSV，就能看到昨日 GMV / 访客 / 转化率 / 客单价 / 退款率的环比与近 7 天汇总。
- 作为店主，当出现流量骤降 >30%、退款率 >8%、转化率环比降 >25% 时，系统自动标红并给出排查建议。

## 4. 功能范围
| 模块 | 说明 |
|---|---|
| 数据导入 | 兼容生意参谋导出格式（中文字段），utf-8-sig 兼容 BOM |
| 指标计算 | GMV、转化率、客单价、退款率、近 7 天汇总 |
| 异常检测 | 阈值规则（流量 ±30%、退款率 8%、转化降幅 25%），可配置 |
| 建议生成 | 业务规则映射表：什么异常 → 排查什么（可解释、可审计） |
| 日报文本 | 规则模板拼接；可选接大模型做口语化润色（见项目一/二接入方式） |

## 5. 非目标（边界，面试主动说明）
- 不做自动改价、自动补货、自动调投放——只给"建议"，动作由人执行（合规红线）。
- 不接真实平台 API；示例数据为公开演示数据。

## 6. 设计亮点（面试可讲）
- **先规则后模型**：归因与阈值是确定性业务逻辑，用规则保证可解释、零成本；大模型只做可选的"润色"增强。
- **阈值配置化**：`TH` 一处修改即可适配不同类目/体量店铺。

## 7. 运行
```bash
pip install -r requirements.txt
python app.py   # http://127.0.0.1:5003
```
演示模式无需任何 API key，点击"生成日报"即用示例数据跑通全流程。

## 8. 简历写法（诚实版）
- 「设计经营数据日报工具：规则化异常检测（流量/退款率/转化率）+ 建议映射，替代人工抄数，输出可解释日报」（个人项目）
