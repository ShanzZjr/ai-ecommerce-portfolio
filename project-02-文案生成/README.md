# 项目二：商品文案生成 + 违禁词检测 —— 需求文档（PRD）

> 定位：个人练手项目，模拟「AI 产品 / 运营」用生成式 AI 解决上新文案慢、违规被罚两个痛点。

## 1. 背景与痛点

- 上新时标题、五点描述、详情页文案靠人写，慢且不一致。
- 非专业卖家容易踩**极限词 / 违禁词**（最、第一、100%真皮、原单…），被平台判违规、扣分、罚款。
- 人工自查效率低，且对最新规则不敏感。

## 2. 目标用户与场景

- 中小电商卖家做日常上新；本项目以「包包」为示例类目。
- 场景：批量生成初稿 → 自动过合规 → 人工微调发布。

## 3. 功能需求（FR）

| 编号 | 功能 | 说明 | 优先级 |
|------|------|------|--------|
| FR1 | 结构化输入 | 品类/材质/颜色/尺寸/卖点，避免自由文本噪声 | P0 |
| FR2 | 文案生成 | 大模型按模板输出 标题+五点+详情页结构 | P0 |
| FR3 | 违禁词检测 | 本地词表匹配，标记极限词并给原因 | P0 |
| FR4 | 高亮展示 | 命中词前端标红，便于人工一眼看到 | P1 |
| FR5 | 演示模式 | 无 key 返回模板化示例，流程可演示 | P1 |

## 4. 非功能需求（NFR）

- 生成 + 检测单次 < 5s。
- 违禁词表可配置、可随平台规则更新。
- 生成结果**仅作初稿**，发布前需人工确认（不免责）。

## 5. 关键设计决策（面试可讲）

- **为什么生成后还要本地检测，而不是让模型「自己别用极限词」？** 模型不可靠，合规是硬约束，必须用确定性的规则兜底，符合「AI 输出 + 规则校验」的工程范式。
- **为什么词表本地化而不是调接口？** 合规词表是店铺自己的资产，本地可控、零成本、可审计，且离线可用。
- **生成与检测解耦**：生成失败不影响检测，检测失败不影响生成，各自可替换模型/词表。

## 6. 验收标准

- [ ] 输入结构化信息能产出标题+五点+详情页结构
- [ ] 文案含极限词时被标红并列出原因
- [ ] 不填 key 可进入演示模式
- [ ] 人工能在发布前看到全部风险点

## 7. 边界与风险（诚实说明）

- 词表覆盖有限，新违规词需持续补充；不能替代平台审核。
- 生成文案仍需人工核对「图文一致」，避免 AI 编造参数。
- 演示模式文案为模板，不等于真实商品。
